결정적 geometry를 명확하게 조합합니다.

Core는 논리 layout을 소유하고 host는 rendering, 측정 조정, 접근성, scroll을 소유합니다.

조정된 0.3.0 package를 사용합니다. License는 MIT입니다.

Core 개념

Core는 immutable item과 aspectRatio를 받고 container-relative cell을 반환합니다. 세로는 x/column이 cross, y가 flow이며 가로는 y/row가 cross, x가 flow입니다.

const layout = calculateMasonryLayout(items, {
  containerWidth: 960,
  minColumnWidth: 220,
  gap: 8,
});

입력 순서가 canonical입니다. layout.cells, ID, cell.index는 source 순서를 유지합니다.

배치

연속적인 columnSpan/rowSpan을 사용합니다. preferred lane은 soft intent이고 locked lane은 hard logical 제약입니다. flowDistribution은 start, end, center, space-between, space-evenly를 지원합니다.

전체 item 측정값은 세로에서 { height, forWidth }, 가로에서 { width, forHeight }입니다. ReservedRegion은 논리 { laneStart, laneSpan, flowStart, flowSize } hard obstacle이며 synthetic cell을 만들지 않습니다.

측정 lifecycle

Core가 cross size를 정하고 host가 natural content를 render/measure한 뒤 cross-size-bound resolvedFootprint을 전달합니다. absolute-positioning shell을 측정하지 마십시오. 오래된 binding은 ratio geometry로 fallback합니다.

상태, snapshot, stable reflow

createMasonryState는 append, update, remove, reorder, resize, inspect, snapshot, restore를 제공합니다. Snapshot은 같은 semantic 상태를 위한 검증된 checkpoint이지 undo/history가 아니며 stale/tampered restore는 원자적으로 실패합니다.

reflowStrategy: "stable"은 compact와 retained-lane 후보를 total displacement, maximum displacement, moved count 순으로 비교하고 동률이면 compact를 선택합니다. 전역 optimizer가 아닙니다. calculateFlowAnchorDelta는 geometry만 반환합니다.

방향

flowDirection은 flow 축만, crossDirection은 cross 축만 mirror합니다. source/DOM 순서나 text RTL을 자동 변경하지 않습니다. Vertical RTL-style 화면에서는 host가 cross reverse와 별도의 DOM/accessibility 정책을 선택합니다.

Reserved regions

Region은 논리 hard obstacle입니다. 겹침과 배열 순서는 geometry를 바꾸지 않고 shared lane item은 flow gap을 지킵니다. Region extent도 layout extent에 포함됩니다. Dense/backfill은 구현되지 않았습니다.

진단, query, tolerance

calculateMasonryLayoutWithDiagnostics는 opt-in이며 일반 layout과 동일한 layout 및 span/lane/footprint/obstacle/distribution 사실을 반환합니다. Linear/index query는 동등하고 virtualization은 scroll을 소유하지 않습니다.

flowTolerance는 lane candidate 선택 band만 넓힙니다. 선택된 lane의 정확한 좌표와 gap/collision 규칙은 변경되지 않습니다.

React와 Browser adapter

React는 MasonryGrid, HorizontalMasonryGrid, layout hook, useOrderList, virtualization hook을 제공합니다. Browser는 세로/가로 controller와 virtualized lifecycle을 제공합니다. 두 adapter 모두 Core geometry를 사용하고 DOM/scroll 정책은 host에 둡니다.

제한과 상태

  • Dense/backfill과 React Native는 deferred입니다.
  • Core는 DOM, text direction, accessibility, scroll을 소유하지 않습니다.
  • 일부 state 설정은 전체 재계산을 사용합니다.
  • Region 수가 많으면 obstacle 처리 비용이 증가합니다.
